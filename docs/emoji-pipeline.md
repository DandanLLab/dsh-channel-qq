# 表情包完整方案（脱敏增强版）

> 从 DandanLLab/dsh-channel-qq 内部运行版提炼的完整表情包管线，供上游参考融合。
> 脱敏：不含本机路径、账号、群号与内部日期令。

## 一、为什么需要闸门（血泪依据）

表情包库曾发生过**截图混库事故**：群友甩手机截图/聊天记录长图，被当成表情包偷进了库，
打标后发现"库里 909 张里 22 张是聊天记录"。事后全库视觉复核 909→887 全真，
并沉淀出三条硬闸（下面第二节）。教训：**入库前不看内容，出库就丢人**。

## 二、入库三闸（`EmojiStore.steal`）

偷图前按**字节魔数**判真实格式（QQ 链接后缀会说谎），再逐张体检：

1. **格式闸**：真实格式必须是 `png / gif / jpg`（魔数嗅探）。
   `webp` 与未知格式一律拒收——webp 动画在 QQ 端显示不稳，未知格式解码必错。
2. **EXIF 闸（jpg）**：手机截图必带 EXIF，真表情包过手聊天工具极少带——
   `buf.includes(Buffer.from('Exif'))` 命中即拒收。这是拦截"私照/截图"最便宜也最准的一刀。
3. **形状闸（jpg + png）**：
   - jpg：`宽高均≥1000 且体积≥140KB` = 照片/截图拒收；
     `max(w,h)/min(w,h) ≥ 1.9`（竖长聊天记录/横幅）拒收；
     `h≥2000 且 ≥100KB` 竖长图拒收。
   - png：读 IHDR（offset 16/20 的 u32 宽高），同样按 1.9 长宽比拒收。

被拒的图**只写日志不入库**，日志行格式 `sticker rejected: <原因>`，事后可审计。

## 三、发送侧严格后缀（`qq_send_emoji` 链路）

QQ native 按文件后缀选解码器（NapCat `Ti()` 后缀原样透传）：

- 发送前再读一次字节魔数，若路径后缀 ≠ 真实格式
  （1143 张 `.png` 实为 jpg、616 张实为 gif 的教训），复制一份**带真实后缀**的临时文件再发，
  30 秒后自动清理。原图字节零修改。
- 效果：`.gif` 后缀必然发成动画表情；透明 png 不被 jpg 解码器糊底。

## 四、词法 MISS 不静默：三级兜底（`qq_send_text` 里的 `[表情: 描述]` 标记管线）

模型在正文里写 `[表情: 描述]` 标记，出站层剥标记换成真图：

1. **meme pack 优先**：`send_meme` 候选的 caption 就在 pack 索引里，描述必须能对上——
   先查 pack（词全命中 → bigram 兜底）。
2. **原生库次之**：emoji-library `search(desc, 1)`，描述命中权重 5、标签 3、
   同义词扩展、**单字降权 0.4**（"哼"不压"委屈"；多词按空白/标点切词，
   旧逻辑整串 includes 对"哼 委屈"这类必空）。
3. **词法 MISS 转语义**（关键升级，不做静默丢弃）：
   - 先走 meme pack **关键词直搜**（关键词 + bigram 计分，阈值 ≥3）；
   - 仍落空才走**向量语义兜底**（KB `brain "表情包 <描述>"` 检索）；
   - 三级全 MISS：**明确记日志 `emoji semantic miss`，标记按文字表情原样发出**
     （2026-10-31 升级，替代旧"此条不发图"）——宁可发文字，不发一张
     驴唇不对马嘴的图；标记不再整条吞掉，情绪表达零蒸发。
     quote 路径（`qq_reply_quote`）无语义兜底，词法落空即按文字表情留在原位。

## 五、打标与索引

- 索引 schema：`md5 → { file, source, desc, tags, type }`，MD5 去重；
- 视觉打标走 harness LLM 缝隙，**描述（desc）是亲眼写的语义锚**，检索权重最高；
- `type` 字段区分 `emoji`（卡通/梗图/带字表情）与 `image`（截图/照片）——
  语义搜索时 image 类默认沉底；
- 伪装错格式的存量库：按魔数普查重命名 + 索引路径同步（一次性迁移脚本思路，
  逐张嗅探、0 误判）。

## 六、给上游（Aegink fork）的对接点

fork 的 `features/stickers`（EmojiStore/EmojiLibrary）与本文方案同源，缺的是：

| 缺口 | 对应本文 |
|---|---|
| 入库无 EXIF 闸 | 第二节第 2 条（一行 `includes('Exif')`） |
| 入库无形状闸（长宽比/大图） | 第二节第 3 条（jpg SOF 扫描 + png IHDR 各 ~15 行） |
| 发送无魔数-后缀一致性校验 | 第三节（临时文件重后缀法） |
| 检索单字等权、MISS 静默 | 第四节（单字 0.4 降权 + MISS 三级兜底 + 落空按文字表情发出） |
| 无 `type` 分类字段 | 第五节（emoji/image 分型，搜索沉底） |

以上全部为纯本地字节操作 + 检索策略，零新依赖、零外部调用，可直接移植。
